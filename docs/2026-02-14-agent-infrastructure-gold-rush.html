The Agent Infrastructure Gold Rush

2026-02-14ai, agents, startups

Everyone's building AI agents. Almost nobody is asking what the agents will run on.

The Picks and Shovels Thesis

In 1849, the people who got rich in the California Gold Rush mostly weren't miners. They sold pickaxes, jeans, and ferry rides. The actual gold was a lottery. The infrastructure was a business.

We're watching the same pattern replay in AI agents. The big demos are impressive: agents that book flights, manage inboxes, negotiate contracts. But here's the quiet problem: every one of those tasks requires the agent to interact with systems designed exclusively for humans.

An agent needs to send an email? It needs an email address. It needs to authenticate. It needs to not get flagged as spam by every provider on Earth. It needs somewhere to receive replies. It needs to parse those replies, which arrive in formats ranging from clean plaintext to unhinged HTML that looks like it was written during a fever dream in 2003.

An agent needs to browse the web? It needs a browser session, cookies, headers that don't scream "I am a bot," and a way to handle CAPTCHAs, rate limits, and the fifteen different ways a modern website can detect automation.

An agent needs to pay for something? Identity. Bank account. Fraud checks. Compliance.

Every single human primitive (email, phone, identity, payments, browsing, scheduling) needs an agent-native equivalent. Right now, almost none exist.

The Landscape

It's early, but the pieces are appearing.

Email is the first battleground. AgentMail (YC-backed) gives agents their own email addresses with full API access: send, receive, parse, thread, manage inboxes programmatically. No IMAP. No OAuth dance. Just an API that treats email as structured data rather than a legacy protocol you're screen-scraping. There's also Bax.email, taking a similar angle. The fact that multiple startups are converging on "email, but for agents" tells you the demand is real.

Browser automation is its own category now. Not Selenium-era "click this pixel coordinate and pray." Agent-native browsing means giving an LLM a structured representation of a page and letting it act. Tools like Browserbase, Steel, and others are building headless browser infrastructure specifically for agent workloads: handling sessions, proxies, fingerprints, and all the miserable plumbing that makes web automation actually work at scale.

Identity and auth is the sleeper. Today's agents piggyback on human credentials, which is both a security nightmare and fundamentally unscalable. An agent acting on your behalf needs scoped, revocable, auditable permissions. Not your Google password in a .env file. Nobody's really cracked this yet, which means someone will.

Payments barely exist. Agents can't hold money, can't have bank accounts, can't pass KYC. Stripe has a foot in the door with their agent toolkit, but the full picture (an agent with its own financial identity, spending within budgets, handling refunds) is still science fiction.

Why This Matters

The agent layer is a new computing platform. And platforms need infrastructure.

When mobile took off, the money wasn't just in apps. It was in push notification services, analytics SDKs, crash reporting, payment processing, mapping APIs. The entire mobile ecosystem runs on infrastructure that didn't exist in 2007.

Agents are following the same arc. The demos are ahead of the plumbing. Everyone's showing agents that can "do anything," but behind the curtain there's a developer hand-wiring SMTP connections and hardcoding session cookies. That's not a product. That's a prototype held together with string.

The companies building the boring middle layer (agent email, agent auth, agent browsing, agent payments) are building what will become as essential as Stripe is to web commerce or Twilio is to communications. Unsexy, indispensable, and extremely difficult to rip out once integrated.

The Risk

The risk is timing. Picks-and-shovels businesses need miners. If agent adoption stalls, if the reliability gap doesn't close, if users don't trust agents with real tasks, then agent infrastructure is a solution looking for a problem.

But I'd bet against that. The trajectory is clear. Models are getting better at agentic tasks faster than most people expected. The constraint isn't intelligence anymore. It's access. Agents are smart enough to send emails, browse the web, and make purchases. They just can't.

That gap is where the money is.

The Bottom Line

If you're starting a company in the agent space, think hard about whether you want to be the miner or the one selling pickaxes. Miners compete on who found the best gold vein this week. Pickaxe sellers compete on who built the most reliable tool.

One of those is a venture-scale business. The other is a demo.

Every human primitive needs an agent-native equivalent. The startups building them will be boring, essential, and very profitable.
